## 🚀 Nexus-Stream 全场景高性能流媒体转码网关 —— 产品需求文档（MVP 专家作品版）## 一、 产品定位与核心价值
在远程兼职市场中，雇主对音视频项目的诉求主要集中在两个极端：要么是传统的局域网摄像头（RTSP）网页化无插件低延迟播放，要么是无人机、应急车载（SRT/RTMP）在 4G/5G 弱网环境下的高清推流转码分发。
本系统定位为全场景多协议流媒体中转网关。它同时向下兼容传统的安防拉流，向上攻克移动弱网推流，通过 C++/Go 混合媒体流处理技术，解决低算力硬件与高并发转码之间的矛盾。
------------------------------
## 二、 系统角色与服务定义## 2.1 Nexus-Ingress（流量接入网关）

* 定位：靠近设备受控端的轻量级接入层。
* 核心职责：
* 主动拉流：根据通道配置，主动拉取局域网内海康、大华等安防摄像头的 RTSP/ONVIF 原始流。
   * 被动接流：在边缘端开放固定网络端口，专门接收来自无人机、运动相机的 SRT/RTMP 弱网高清流（H.265格式）。
   * 流量中转：自身不做任何重型转码计算。通过高并发 gRPC 双向流（Streaming） 隧道，将接收到的媒体原始包无损、单连接多路复用投递给远端的 Nexus-Core。

## 2.2 Nexus-Core（媒体核心/转码与分发中心）

* 定位：整个系统的硬核大脑，支持本地或 GPU 云服务器弹性部署。
* 核心职责：
* 双轨制硬件探针：启动时执行显卡探针。有 GPU 时激活 NVIDIA NVENC 硬件加速执行 4K H.265 到 1080P H.264 的无感硬转；无 GPU 时自适应触发降级，执行 CPU 抽帧自愈过滤器（强降 12fps / 540P），确保系统不卡死。
   * 动态路由与鉴权：截取推流 StreamKey，通过内置 SQLite 进行合法性校验，通过后才允许 C++ 初始化转码管道。
   * WebRTC/HLS 多协议分发：集成本地分发层，直接将转码后的 H.264 转化为标准的 WebRTC 格式（低延迟 <300ms）分发给现代浏览器，并提供 HLS 弱网兼容兜底。

## 三、 硬核技术栈选型（兼职接单杀手锏）
为了在程序员客栈支撑起高客单价（1W-5W）的流媒体定制单，技术栈必须展现出高技术壁垒：

| 层次 | 选型 | 选用理由（如何说服雇主） |
|---|---|---|
| 流媒体网络层 | Go (Pion/WebRTC + gRPC) | 借助 Go 语言的 Channel 和读写锁 RWMutex 实现高并发 RTP 包分发；pion/webrtc 负责原生 ICE 穿透与信令交互；gRPC 双向流保障 Ingress 到 Core 的单隧道多路复用。 |
| 流媒体媒体层 | C++ (libsrt + FFmpeg API) | 在内存中玩二进制，不碰网络和业务。调用 libsrt 维护 UDP 接收缓冲区与丢包重传（ARQ）；通过 FFmpeg 硬件加速接口（AV_HWDEVICE_TYPE_CUDA）直接在 GPU 显存内完成 H.265 到 H.264 的像素级转换，完美避开 Go 的 GC 延迟。 |
| 持久层与业务管理 | SQLite + GORM | 保持“单二进制、极简部署”的特色，免去复杂的云端数据库配置，支持离线或边缘一体化盒子直接交付。 |
| 可视化看板前端 | Vue 3 + WebSocket + ECharts | 实现技术指标秒级无刷新联动。将 C++ 底层内核统计到的 实时编码器、转码模式（GPU/CPU）、4G弱网实时丢包率、实时带宽、FPS 动态渲染到大屏看板上。 |

## 四、 核心数据模型设计（SQLite）## 4.1 资产与鉴权配置表 (devices)
记录全网允许接入的视频源（无论无人机推流还是摄像头拉流）。

* id: INTEGER (主键)
* device_name: TEXT (设备/通道名称，如“大疆御3-巡检01”或“一楼大门口摄像头”)
* stream_key: TEXT (推流/拉流专属密钥，防伪造)
* direction_type: TEXT (PUSH 代表无人机推流 / PULL 代表网关主动拉 RTSP)
* rtsp_url: TEXT (当为 PULL 模式时，摄像头拉流地址)
* status: TEXT (当前状态：ONLINE 直播中 / OFFLINE 离线 / DEGRADED 降级中)
* last_active_at: DATETIME (最后一次心跳或流活跃时间)

## 4.2 实时流媒体技术指标表 (stream_sessions)
用于向大屏高频同步流媒体底层的元数据，体现系统的“硬核技术感”。

* id: INTEGER (主键)
* device_id: INTEGER (关联的设备 ID)
* current_codec: TEXT (当前转码输出编码，如 H.264 (NVENC) 或 H.264 (libx264))
* transcode_mode: TEXT (转码轨道：GPU_ACCELERATION 或 CPU_SELF_HEALING)
* bitrate_kbps: INTEGER (实时拉/推流带宽)
* fps: INTEGER (实时帧率)
* loss_rate: TEXT (移动 4G/5G 弱网下的实时网络丢包率)
* resolution: TEXT (当前输出分辨率，如 1920x1080 或 960x540)

## 五、 3天“瞒天过海”MVP 闪电通关计划（快速出录屏）
作为兼职作品，我们不需要在初期手写完上万行 C++ 代码。通过“壳架构”伪装策略，用最少的代码把全链路的双轨制切换、大屏联动特效跑通，录制出极具说服力的演示视频去客栈接单。
## 📅 第 1 天：搭建 Go 骨架与“FFmpeg 伪装内核”

* 任务 1：编写 Nexus-Ingress 和 Nexus-Core 的 Go 服务基础框架，使用 gRPC Stream 或本地进程通信打通控制流。
* 任务 2：编写 Go 的 os/exec 自适应媒体管道。
* 检测到环境变量 FORCE_GPU=true 时，Go 异步调用本地 FFmpeg 命令行并注入 -vcodec h264_nvenc 模拟显卡硬转。
   * 检测不到 GPU 时，自动注入 -vcodec libx264 -r 12 -s 960x540 模拟系统触发无显卡抽帧自愈降级。

## 📅 第 2 天：打通 WebSocket 动态指标与 Vue 3 炫酷大屏

* 任务 1：在 Go 后端建立 WebSocket 广播服务，每隔 1 秒将 FFmpeg 状态以及波动的数据（FPS、丢包率等）以 JSON 格式推向前端。
* 任务 2：用 Vue 3 编写极简播放器页面（利用 WebRTC 标签挂载），并在右上角写一个极具科技感的 Dashboard 看板。
* 当接收到 GPU 模式信号：界面亮起极客绿 [🟢 边缘/云端显卡托管高性能转码中]，ECharts 曲线图展示 60fps 丝滑状态。
   * 当接收到 CPU 模式信号：界面瞬间切为警告黄 [⚠️ 系统未检测到显卡，已自适应切换为云端 CPU 抽帧自愈降级轨道]，FPS 曲线跌落至 12fps。

## 📅 第 3 天：录制 30 秒高亮演示视频，上架程序员客栈

* 实操动作：在电脑上分别以有显卡、无显卡两种环境变量启动后端，刷新网页，录制界面在 1 秒内从“极客绿高帧率”瞬间切换到“警告黄抽帧自愈”的震撼对比。
* 上架发布：将本 PRD 与第 1、2 天写出的纯 Go/Vue 代码开源，将 30 秒录屏挂在程序员客栈的作品集首页，开始降维打击流媒体兼职订单！
